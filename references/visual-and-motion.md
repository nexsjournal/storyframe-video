# 视觉与运动

## 1. 一套视觉系统，不是一堆素材

每个项目先定 6 个变量：

1. **一个核心隐喻**：纸/墨、光/棱镜、地图/路线、仪器/刻度、舞台/幕布。
2. **一个主色 + 一个强调色 + 一个底色**：不要超过 5 个高频颜色；多色系统要有映射规则（颜色=乐器/类别/步骤）。
3. **一套字体**：display（大标题）/ body（说明）/ caption（字幕）；中文无衬线优先，英文可用 grotesk/ condensed。
4. **一个网格**：12 列、margin、gutter；所有场景共用。
5. **一个材质**：纸纹、噪点、扫描线、玻璃、金属、像素；只选一个主材质。
6. **一个运动规则**：相机推拉幅度、字体 stagger、转场时长、easing。

写进 `DESIGN.md` 或 `DIRECTION.md`，不要每镜临时决定。

## 2. 排版

### 层级
- **一级**：主张/数字/产品名；占画面 40–70%。
- **二级**：解释/步骤；18–32px（1080p）。
- **三级**：注释/来源；14–20px，低对比。
- 一屏最多 2 个层级同时抢注意力。

### 字重/字距
- 大标题用 Black/ExtraBold，字距 −2% 到 −5%（中文不要负太多）。
- 正文用 Medium/Regular，行高 1.4–1.6。
- 全大写英文加 4–8% 字距；中文不要全大写式拉宽。

### 对比
- 深底浅字或浅底深字；不要中间灰对中间灰。
- 强调色只给关键词/数字/按钮；不要整段染色。
- 背景有纹理时，文字加轻微阴影/描边/底板，保证可读。

## 3. 构图

- **中心**：适合宣言/产品/仪式感；用对称或强透视。
- **偏心**：适合叙事/对比；留白给动作。
- **三分/网格**：适合信息/步骤；保持稳定。
- **满版**：适合冲击/副歌；文字要少。
- **画中画/UI 卡片**：适合产品演示；注意透视和阴影统一。

不要每个镜头都居中；也不要每个镜头都斜着放。

## 4. 运动词汇

### 相机
- **push in**：1.00→1.04–1.10，2–4s；强调/进入。
- **pull out**：1.10→1.00；揭示/收尾。
- **pan/tilt**：跟随主体；速度与 beat 对齐。
- **orbit/rotate**：3D 产品/纸面；5–15°，不要晕。
- **parallax**：前景/背景不同速度；制造空间。
- **whip pan**：快速甩；接硬切/闪白；不要连续用。

### 字体
- **mask reveal**：从下往上/从左到右；适合标题。
- **per-char stagger**：20–50ms/字；适合歌词/主张。
- **blur-in**：12–20px→0，150–300ms；适合副歌/冲击。
- **scale slam**：1.15→1.00，80–120ms；适合重拍。
- **tracking expand**：字距拉开；适合结尾/呼吸。
- **split/flip**：单词/字母翻转；适合科技/节奏，不要滥用。

### 转场
- 硬切（beat）、闪白（2–3 帧）、颜色 wipe、扫描线、材质遮罩、match cut、whip、物体带出。
- 每个转场写“为什么”：时间跳/空间跳/信息跳/情绪跳。

### 材质/粒子
- 纸纹/墨迹/笔刷：手作/创作/教育。
- 扫描线/像素：数字化/读取/音乐生成。
- 光/辉光：舞台/能量/副歌；不要全片泛光。
- 粒子：只在“汇聚/爆炸/数据流”有叙事意义时用；不要背景装饰。

## 5. 节奏

- **promo**：1.5–3s/镜；副歌 0.8–1.5s/镜；结尾 2–4s。
- **explainer**：4–8s/概念；图解 build 2–3 步。
- **course**：5–10s/步；等待加速。
- **event**：0.8–2s/镜；信息镜头 2–3s。
- **mv**：按 beat/bar；副歌可以 1–2 bar/镜，主歌 2–4 bar/镜。

不要用“统一 2 秒”切全片；节奏要有呼吸：快—慢—快。

## 6. 反 PPT 检查

- [ ] 每个镜头有运动/转场/主体动作？
- [ ] 连续静态卡片 ≤2？
- [ ] 标题入场至少 2 种？转场至少 3 种？
- [ ] 没有“标题+三行 bullet”重复？
- [ ] 图解是“构建出来”的，不是一次性贴上去？
- [ ] 背景不是通用粒子/科技蓝？
- [ ] 每个视觉手法能追溯到主题？

## 7. 代码驱动舞台

推荐结构：

```html
<div id="stage">
  <div id="bg"></div>       <!-- 底色/纹理/渐变 -->
  <div id="world"></div>    <!-- 产品/主体/3D -->
  <div id="type"></div>     <!-- 标题/字幕 -->
  <div id="fx"></div>       <!-- 光/粒子/扫描 -->
  <div id="vignette"></div> <!-- 暗角/噪点 -->
</div>
```

`window.seek(t)` 必须是 **纯函数**：同一 `t` 渲染同一帧，不依赖 `Date.now()`、随机数、CSS transition 的墙钟时间。

- 所有随机用 seeded random；所有动画由 `t` 计算。
- 字体加载完再 `window.__READY__ = true`。
- 截图前 `await page.evaluate(t => window.seek(t), t)`；等 1 帧 `requestAnimationFrame`。
- 不要在渲染循环里读网络/数据库。

## 8. 竖屏重排

- 不要直接裁 16:9；重新排层级：主体居中偏上，字幕在下 20%。
- 大字占宽 80–90%；一行中文 ≤10–12 字。
- 产品 UI 竖屏可做“局部放大 + 画中画”，不要缩成一条。
- 安全区：上 12%、下 18% 避开平台 UI。
- 首帧同样完整；二维码在竖屏至少 22% 宽。

## 9. 视觉验收

- 手机大小（25%）看：标题是否可读？主体是否清楚？
- 静音看：信息是否靠字幕/画面成立？
- 抽 3 帧给没看过的人：能否说出这条片子在讲什么？
- 去掉颜色看：层级是否还成立？
