# 口播优化与课程演示

这两种模式都依赖“原片”，不是从零做动效。核心是：**先让信息清楚，再让画面好看**。

## A. 口播优化（oral）

### A1. 输入
- 原始视频/音频（最高画质；不要先压缩）
- 带时间戳的 transcript
- 产品/B-roll 素材
- 专有名词表（人名/产品名/缩写）

### A2. Paper edit
1. 标出 **钩子**：原片里最有能量/最反常识的一句，放到 0–2s。
2. 标出 **重复**：同一个意思说两遍，留更清楚的那遍。
3. 标出 **filler**：嗯/那个/就是/然后；可删。
4. 标出 **false start**：说了半句重来；删前半。
5. 标出 **长停顿**：>500ms 且无情绪；压缩到 200–300ms。
6. 标出 **必须保留**：数字、承诺、情绪、笑点、品牌名。
7. 写成一列“保留句”，按逻辑排序；不要按拍摄顺序。

### A3. 粗剪
- 先只剪音频，画面先不动；听一遍是否顺。
- 用 J-cut/L-cut：声音先入/后出，避免每个切都硬断。
- 跳剪用 B-roll/放大 1.05–1.15/轻推/图形遮罩；不要用花哨转场掩盖所有切点。
- 语速最多 1.1–1.2x；再快就听不清。
- 删除超过 1.5s 的无信息停顿；保留呼吸/笑/情绪停顿。

### A4. 字幕
- 中文 12–16 字/行，最多 2 行；英文 38–42 字符/行。
- 每条 1.5–4s；不跨语义。
- 关键词/数字/产品名可加粗/变色；不要整句高亮。
- 烧录 + SRT；SRT 给平台/无障碍。

### A5. B-roll / 画面
- 每 3–5s 至少一个画面变化：B-roll、放大、图表、关键词卡。
- B-roll 要“解释”这句话，不是随便铺。
- 人物口播时，不要一直全屏脸；用画中画/切手/切产品。
- 关键词卡停留 ≥1.2s；不要和字幕重复。

### A6. 声音
- 降噪（轻）、高通 80–100Hz、2–5kHz +1–2dB、压缩 3:1–4:1、去齿音。
- 音乐在口播下 −3 到 −6dB；口播间隙可抬。
- 关键句 1–2 个音效；不要每句都加。
- 整体 −14 LUFS（web）/ −16 到 −14（课程）。

### A7. 验收
- [ ] 0–2s 有钩子
- [ ] 没有“嗯/那个”残留
- [ ] 语速不超过 1.2x
- [ ] 字幕同步、≤2 行
- [ ] 静音能看懂
- [ ] 手机外放人声清楚
- [ ] 结尾 CTA 具体

## B. 课程演示（course）

### B1. 目标
写一句“学完能做什么”：
> 看完这 90 秒，你能把一张草图导出成 10 秒动画。

不要写“介绍一下这个功能”。

### B2. 步骤设计
- 3–5 步；每步一个动作 + 一个结果。
- 先写步骤清单，再录屏；不要边录边想。
- 每步包含：前置条件、点哪里、发生什么、成功标志。
- 常见错误单独 5–10s；不要假装不会出错。

### B3. 录屏
- 1920×1080 或更高；30/60fps；关闭通知/隐私信息。
- 鼠标/手指可见；点击有反馈。
- 等待/加载加速 2–8x；用进度条/时间戳提示。
- 不要录整个桌面；只录应用窗口。
- 关键设置放大 1.5–2x；不要缩小整个 UI。

### B4. 剪辑
- 每步开始加 0.3–0.5s 停顿/编号卡。
- 步骤之间用硬切/轻推；不要花哨转场。
- 关键点击加圆圈/箭头/放大；标注指向“正在说的那个东西”。
- 结果展示 2–3s；让观众看清。
- 每 30–45s 一个小结/进度。

### B5. 声音
- 口播 3.5–4.5 字/秒；比广告慢。
- 点击/键盘音可保留，但降到底噪以下；不要每点都加音效。
- 背景音乐 −20 到 −24dB，不抢口播。
- 课程整体 −16 到 −14 LUFS。

### B6. 验收
- [ ] 学完能复述 3 个步骤
- [ ] 没有跳步/前置条件缺失
- [ ] 关键 UI 在手机大小可读
- [ ] 鼠标/点击可见
- [ ] 等待时间已加速
- [ ] 结果展示清楚
- [ ] 有 recap/练习
- [ ] 字幕同步

## C. 两种模式的共同禁忌

- 不要把“口播”剪成没有呼吸的 AI 念稿。
- 不要用 B-roll 盖住关键信息。
- 不要用 10 种转场；课程/口播以清楚为先。
- 不要让字幕和画面文字重复。
- 不要为了“节奏”删掉必要条件/限定词。
- 不要在没看完整片的情况下交付。
