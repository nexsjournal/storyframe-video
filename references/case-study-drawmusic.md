# 案例：绘声绘色 48.8s 产品推广 MV

这是一个真实完成的项目，用来展示“方向—分镜—代码—声音—验收”的完整链路。不要照搬它的视觉，照搬它的**推导方式**。

## 1. 约束

- 歌曲：用户提供 `绘声绘色.mp3`，48.84s，48kHz 立体声，127.84 BPM，约 27 小节。
- 产品：绘声绘色 Draw Your Music，把绘画变成音乐；九种颜色对应九种乐器。
- 场景：观猹大会·猹工坊，展位 G11，10.24–10.25，杭州·龙坞。
- 要求：有节奏感、产品主题、不是幻灯片、完整声音设计；参考一支动态字/3D UI 的 MV。
- 交付：1920×1080 / 30fps / 48.8s / H.264 / AAC。

## 2. 方向

**纸 + 墨 + 九色**：产品界面是一张会发声的纸；线条决定旋律，位置决定音高，颜色决定音色，扫描线把画点亮。

专属手法：

1. 纸纹/墨线/奶油底，区别于参考片的暗紫星云。
2. 九色=九乐器：每次落色有独立色块 + 音色。
3. 扫描线/读取头/像素点亮：转场来自“扫描画作”。
4. 副歌把 UI 变成 3D 纸面海报：不是静态大字，而是相机推拉/倾斜。
5. 结尾 G11/日期/二维码：活动信息是歌的一部分。

| 5.8–11.4 | 画高/颜色 | 红黄绿蓝紫线条，音符从线上升起 | 每色一个音色 |

## 4. 声音

- 52 个合成音效 cue，13 类：brush/pencil/stamp/bell/chime/whoosh/riser/impact/scan/sparkle/glitch/tape/click。
- 覆盖 0.02–47.55s；关键 impact 与 flash/cut 同帧。
- 人声/音乐下让位；总线 loudnorm。
- 实测：**−10.6 LUFS / −1.0 dBTP / LRA 2.0**（展会/社交偏响）。

## 5. 验收数据

- 时长 48.800s；1920×1080；30fps；H.264 High + AAC 320k。
- 首帧 ink ratio **0.0654**（阈值 0.004），不是空白。
- 逐帧统计 1463 帧：`stillRatio=0.0`，`movingRatio=0.994`，`hardChanges=59`，最长静止 **0.0s**。
- 18/18 歌词块与乐句起点最大偏差 **0.040s**。
- 文件 SHA-256：`0deda0dee15b9b4d73cdcbef67dcafef66fdf881d432c113f0539b24fe0089a4`（以当前文件为准）。

## 6. 踩过的坑（可复用）

1. **首帧不能空白**：开场倒计时的完成态要放在第 0 帧，否则平台缩略图是白纸。
2. **plate 不要半透明**：大字底板淡入太慢，底层线条会穿过去；底板要么快速不透明，要么不要底板。
3. **不要给大字加过重模糊**：132px 字号 + 14px blur 会像打码；入场 blur 控制在 4–8px。
4. **副歌不能静止**：3D 纸面要持续推拉/倾斜；否则中段像 PPT。
5. **结尾不要淡出太慢**：终章和结束卡会叠；用快速父级淡出 + 硬切。
6. **九色段落容易空**：色块/标签/音效要按 85–105ms 逐个落，不要一次性全出。
7. **产品 UI 不能直接缩**：视频尺度要重排；播放条/工具栏要放大到可读。
8. **字幕/大字要避开产品关键 UI**：否则观众不知道看字还是看产品。

## 7. 和 Suno 歌词版的关系

这支 MV 用的是用户最初上传的歌曲与人声；后来用户用 Suno 重写了歌词，要求“轻快、灵动、有旋律记忆点、不是喊麦”。新的歌词生产方法见 `suno-lyrics.md`。

**不要直接把新歌词替换到旧 MV 的字幕上**：旧声轨唱的是旧词，会对不上。正确流程是：先用 Suno 生成新歌 → 分析新歌 BPM/结构 → 按新歌重做 MV。

## 8. 可复用的东西

- 纸/墨/九色的视觉系统（只适用于这个产品，不要套到别的品牌）。
- “颜色=音色”的映射方法。
- 扫描线转场、3D 纸面副歌、播放条微距。
- 52 个音效的 cue 表结构。
- `check_delivery.py` 的验收指标。
