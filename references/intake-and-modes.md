# Intake 与六种模式

## 0. 首轮：先做素材交接

第一次调用不要直接写方案，也不要一次抛 7 个问题。先接住用户已经给的东西，再只问缺的。

**首轮只问三组：**

1. **要什么片**：用途/类型、平台、画幅、时长；看完希望观众做什么。
2. **文案**：有没有现成文案、口播稿、歌词或大纲？粘贴或给路径/链接。有就按原文做；没有就说“没有”，由你起草。
3. **音乐与素材**：有没有音乐/歌曲/配音文件？给路径或链接。产品链接、截图、录屏、Logo、字体、参考片也一起给路径。也可以直接说风格关键词（`UI电影` `纸感` `动态字体` `像素` `Riso` 等）。

用户已经说过的不要重复问。**附件/路径优先**：先读文件、`ffprobe` 看时长/采样率/声道、看截图（BPM 需另测/听），再决定还缺什么。首轮回复用“已收到 / 还缺什么 / 我接下来做什么”，不要只发问卷。

**素材接手规则：**

| 素材 | 先做什么 | 不能做什么 |
|---|---|---|
| 文案/口播稿 | 读全文，标出必须保留句、专有名词、不能改的措辞；复制到 `assets/copy/` 或项目根目录 | 不声不响重写卖点；改动必须记在 `SCRIPT.md` |
| 音乐/歌曲 | `ffprobe` 看时长/采样率/声道；测/记 BPM 与段落；复制为 `audio/music.<ext>`；在 `plan.json` 登记 | 不用生成音乐覆盖；不忽略授权 |
| 配音/原片 | 转写、标时间戳；保留原始文件 | 不先加花字/B-roll 再剪 |
| 截图/录屏 | 看分辨率、空态/完成态/结果；必要时重拍 | 不直接缩小桌面截图当界面 |
| Logo/字体 | 确认 SVG/透明 PNG、授权 | 不描摹/替换品牌字标 |
| 参考片 | 拆结构/视觉/声音三层 | 不直接复刻镜头与配色 |
| 风格关键词 | 查 `style-presets.md`，锁视觉/运动/禁忌；仍给三个叙事方向 | 不把预设当模板直接套 |

**已有工程续做：** 当前目录已有 `BRIEF.md`、`plan.json` 或 `videos/` 时，先读现状、从断点继续；不要重新 intake，不要覆盖已有文件。

## 1. Intake：只问缺失的

目标不是把问卷问完，而是用最少的问题锁定 **一个可交付的承诺**。用户已经说过的不要重复问。下表是完整清单，**不是一次全问**；首轮只问上面三组，其余随流程补。

| # | 问题 | 为什么必须 |
|---|---|---|
| 1 | 这条片子是 product / explainer / oral / event / course / mv 中的哪一种？看完要让观众做什么？ | 决定结构、节奏、素材和验收 |
| 2 | 给谁看？发在哪个平台？16:9 / 9:16 / 1:1 / 4:5？目标时长？ | 决定信息密度、字幕大小、安全区 |
| 3 | 必须出现哪些信息：产品名、卖点、日期、城市、展位、URL、二维码、价格、免责声明？ | 决定结尾和字幕，漏了要重做 |
| 4 | 文案与素材：有没有现成文案/口播稿/歌词/大纲（路径或粘贴）？产品链接/仓库/截图、录屏、人物、Logo、字体、参考视频在哪？ | 决定是“实拍剪辑”还是“代码动效” |
| 5 | 音乐与声音：有没有音乐/歌曲/配音文件（路径或链接）？可商用/需署名？没有就用生成/合成。 | 决定时间基准、卡点和混音 |
| 6 | 语言/人声：中文/英文/双语？需要口播/配音/字幕吗？谁的声音？ | 决定脚本长度和混音 |
| 7 | 喜欢哪支片子的什么？讨厌什么？或者直接说风格关键词（UI 电影/纸感/像素/Riso…） | 避免“科技蓝+粒子”默认审美 |
| 8 | 有哪些限制：claims 证据、版权、deadline、不能出现的人/品牌/信息？ | 防止交付后返工 |

**问风格时**：不要问“你想要什么风格？”——太宽。改成“可以直接说关键词：UI 电影 / 纸感 / 动态字体 / 像素 / 丝网印 / 编辑排版…，也可以给我参考片”。给具体菜单，不要给 20 个形容词。

**不要问**：“时长多少？”如果用户说“随便”——按模式给默认值，并说明理由。

## 2. 模式默认值

| 模式 | 默认时长 | 画幅 | 镜头节奏 | 必需素材 | 主要风险 |
|---|---:|---|---|---|---|
| product | 30–45s | 16:9；社交 9:16 | 1.5–3s/镜 | 真实 UI/录屏/产品图 | 假界面、功能夸大 |
| explainer | 60–120s | 16:9；竖版 9:16 | 4–8s/概念 | 脚本、资料、图示 | 信息过载、念 PPT |
| oral | 30–90s | 9:16 / 16:9 | 2–5s/切 | 原片、transcript | 剪碎、字幕不同步 |
| event | 15–30s | 9:16 / 16:9 | 0.8–2s/镜 | 海报、场地、日期、二维码 | 信息漏、太吵 |
| course | 60–180s | 16:9 / 9:16 | 5–10s/步 | 录屏、步骤、结果 | 步骤跳步、字太小 |
| mv | 歌曲长度 | 16:9 / 9:16 | 按 beat/bar | 歌曲、歌词、视觉素材 | 歌词对不上、静态副歌 |

### 混合模式

- **event + product**：用 event 的 15–30s 节奏，product 的真实 UI 做“现场可玩”的证据；结构是“钩子→现场→产品→CTA”。
- **explainer + course**：用 explainer 的“问题→要点→ recap”，course 的录屏/步骤做证据；不要变成 10 分钟录屏。
- **oral + product**：人物口播为主，产品 UI 做 B-roll/画中画；不要让口播给 UI 让路到听不清。
- **mv + product**：歌曲为主，产品体验做视觉母题；歌词不要变成功能清单。

先写 `primary_mode`，再写 `secondary_mode`（可选）；`plan.json` 里记录。

## 3. 平台与画幅

| 平台 | 推荐画幅 | 时长 | 字幕安全区 |
|---|---|---|---|
| 官网/YouTube/B 站 | 16:9 1920×1080 | 30–120s | 底部 10% 避开平台控件 |
| 抖音/Reels/Shorts | 9:16 1080×1920 | 15–60s | 上 12%、下 18% 避开 UI |
| 小红书 | 3:4 / 9:16 | 15–60s | 下 15% |
| 视频号 | 9:16 / 16:9 | 15–60s | 下 15% |
| 展会大屏 | 16:9 1920×1080 或 4K | 15–30s 循环 | 四周 5% |
| 课程平台 | 16:9 1920×1080 | 60–180s | 底部 8% |

不确定时默认 **16:9 + 9:16 双版**：先做 16:9 母版，再重排安全区/字号，不要直接裁。

## 4. 素材清单

### product
- 产品 URL / 仓库 / 测试账号
- 关键界面截图（空态、完成态、设置、结果）
- Logo（SVG/PNG 透明）
- 品牌色/字体（有授权）
- 真实数据/结果（可公开）
- 竞品/反参考（可选）

### explainer
- 脚本/大纲/资料链接
- 需要引用的数据/图表
- 类比/例子
- 讲师/作者信息（如需署名）

### oral
- 原始视频/音频（最高画质）
- transcript（带时间戳）
- B-roll/产品素材
- 字幕用词表（人名/产品名/专有名词）

### event
- 活动名称、日期、城市、场地、展位
- 海报/主视觉/Logo
- 嘉宾/主办方（如需）
- 报名二维码/URL
- 现场照片/视频（可选）

### course
- 录屏（原始帧率/分辨率）
- 步骤清单/前置条件
- 示例文件/账号
- 结果截图
- 常见错误/分支

### mv
- 歌曲 WAV/MP3（尽量无损）
- BPM/调性/结构（或分析结果）
- 歌词/歌词时间
- 可用的人声/音效/视觉素材
- 品牌/活动信息（结尾）

## 5. Brief 写法

用 `templates/BRIEF.md`。必须包含：

- **一句话承诺**：看完记住什么（不是“介绍产品”）。
- **受众**：谁、在什么场景看、看完做什么。
- **必须出现**：逐项列出，标“必须/可选”。
- **证据**：每个 claim 的来源/日期/范围。
- **限制**：版权、claims、不能出现的内容。
- **假设**：用户没给、你决定了的项。

**Gate A 前必须能回答**：这条片子只推哪一件事？为什么是现在？观众下一步做什么？

## 6. 什么时候要 push back

- 用户要 10 秒讲清 5 个功能：先砍到 1 个核心 + 3 个证据，或改成 30 秒。
- 用户要给未发布功能做“真实演示”：用设计稿/原型要标注“概念”，不能伪装成已上线。
- 用户给的是盗版音乐/字体/素材：要求替换或取得授权，不进入成片。
- 用户要“电影级”但预算/素材只有截图：先对齐“信息清晰 + 节奏好”，不要承诺无法验证的质感。
- 用户要求“不要字幕”但平台静音播放：建议保留可关闭字幕/关键文字上屏。

## 7. 交付前回看

- 这条片子是否回答了 brief 的“一句话承诺”？
- 必须出现的信息是否都在？
- 受众在目标平台、静音、手机大小下能否看懂？
- 有没有为了炫技加入与主题无关的镜头？
