# 快车道：输入已齐，直接出片

当用户已经写好 prompt / 文案，素材和音乐也有文件，**不要再从“三个方向”开始**。快车道把流程压到 5 个阶段、2 个人工点，先出低分辨率预览，再出终版。

## 1. 什么时候走快车道

同时满足以下 3 条，默认走快车道：

- 有可直接使用的 **prompt / 文案 / 口播稿 / 歌词**（用户说“按这个做，不要改”）。
- 素材有路径：截图、录屏、Logo、字体、参考图至少有一类；缺的能明确标成假设。
- 音乐/配音有文件，或用户明确说“没有，帮我生成/合成”。

用户说“别问，直接做”时，也走快车道；只对日期、价格、claim、版权这类高风险信息确认一次。

**不走快车道：** 只有一个模糊想法、没有文案、方向完全没定、需要先做研究和创意比稿。那种情况用标准流程。

## 2. 砍掉什么，保留什么

| 标准流程 | 快车道 | 原因 |
|---|---|---|
| 7 组 intake 问题 | **砍掉**，只核验文件；缺项写进 `BRIEF.md` 的“假设” | 用户已经给了输入 |
| 完整 Research | **压缩**成 claim 核对；只查日期/价格/功能是否可公开 | 不重新发明产品事实 |
| 3 个方向 + 3–6 张高清静帧 | **只做 1 个方向 + 1 张 640 长边 JPEG（16:9 = 640×360）**；最多 3 张 480×270 缩略图 | 方向已由 prompt/参考锁定 |
| 重写脚本 | **保留原文**；只做断句、时间码、字幕行长 | 用户文案是事实源 |
| 完整 animatic 视频 | **用 6–8 张缩略图拼 contact sheet** | 看节奏不需要先渲视频 |
| 1080p rough cut | **640 长边 / 12fps 预览** | 结构问题在低分辨率就能看出来 |
| 4 个 Gate | **2 个人工点**：首帧确认（可跳过）+ 预览确认 | 减少等待和往返 |
| 保留 | 文件核验、首帧设计、`plan.json` 时间覆盖、音画同步、终版 QA | 这些省了会返工 |

## 3. 五个阶段（60 秒片，目标 12–20 分钟）

| 阶段 | 时间 | 做什么 | 产出 |
|---|---:|---|---|
| **F0 接单** | 0–1 min | 读用户点名的 prompt/文案/素材；`ffprobe` 音乐；不扫无关目录 | `BRIEF.md`（含假设） |
| **F1 锁方向** | 1–3 min | 用用户 prompt/风格，只写 1 个方向；渲 1 张 640 长边首帧 | `DIRECTION.md`、`renders/preview/` |
| **F2 铺时间** | 3–6 min | 文案按句切镜；写 `plan.json`；6–8 张 480×270 缩略图 | `SCRIPT.md`、`STORYBOARD.md`、`plan.json` |
| **F3 预览** | 6–12 min | 640 长边 / 12fps / CRF 30 / veryfast 渲一条完整预览 | `videos/preview.mp4` |
| **F4 终渲 + QA** | 12–20 min | 1080p / 30fps / CRF 18 / medium；自动检查 + 3 帧抽检 | `videos/final.mp4`、`QA.md` |

机器慢时，F3 的预览先交付；F4 放后台跑，不要让人盯着进度条。

## 4. 两个人工点

### P1 · 首帧（可选，30 秒）

只发 **1 张 640 长边 JPEG**（16:9 = 640×360），问一句：

> 这个首帧方向对吗？不对我改这一张，不重做三个方向。

用户说“直接做/不用看”就跳过，把选择写进 `DIRECTION.md`，继续。

### P2 · 预览（必须，1 次）

只发：

- `videos/preview.mp4`（640 长边，16:9 = 640×360；12fps；带音轨）
- 一张 6–8 格的 contact sheet（320px/格）
- 一句“只看结构：时长、信息顺序、首帧、音画同步；细节终版再修”

P2 通过后冻结结构。后面只修字幕、颜色、响度、单镜头细节；**不再回到三个方向**。

## 5. 低分辨率对比规则

方向/参考对比只需要看清“整体风格、构图、颜色、字体气质”，不需要 1080p。

| 用途 | 尺寸 | 格式 | 数量 |
|---|---|---|---:|
| 单张首帧/方向确认 | **640 长边**（16:9 = 640×360） | JPEG q72 | 1 张 |
| 多方向并排 | **480 宽/格** | 一张对比表（`still_sheet.py`） | 最多 3 格 |
| 节奏 contact sheet | **320px/格** | JPEG | 6–8 格 |
| 终版细节抽检 | 原尺寸 | PNG/JPEG | 首帧/中段/结尾 3 张 |

命令：

```sh
# 低分辨率首帧：renders/preview/preview_<t>.jpg，640 长边（16:9 = 640×360）
node still.mjs 1.2 4.0 8.5 --preview

# 多方向并排：拼一张带标签的对比表，不逐张发
python3 <skill-dir>/scripts/still_sheet.py renders/preview/*.jpg \
  --out renders/compare.png --label --width 480

# 640×360 / 12fps 预览
node render.mjs --from 0 --to 60 --preview \
  --audio audio/music.mp3 --output videos/preview.mp4

# 终版
node render.mjs --from 0 --to 60 \
  --audio audio/music.mp3 --output videos/final.mp4
```

**不要**为对比图渲 1920×1080 PNG；不要把 12 张参考图逐张塞进上下文；不要先渲完整 1080p 再改结构。

## 6. Token 控制

1. **只读点名文件**：用户给什么读什么；不 `find` 全盘、不读无关参考。
2. **一个方向、一个分镜、一个预览**：变体只在用户明确要求时生成。
3. **把决策写进文件**：`BRIEF.md` / `DIRECTION.md` / `plan.json`；后续从文件继续，不重新推理。
4. **图片用 contact sheet**：一次看 6–8 格，不逐张看 1080p 原图。
5. **确定性工作交给脚本**：时间覆盖、帧数、响度、文件检查不让模型手算。
6. **两轮修改上限**：一轮结构（P2 前），一轮细节（P2 后）；超过就说明输入没锁死，回 F1 而不是无限试。
7. **不重复读长文档**：需要时只读对应小节；已经写进 `DIRECTION.md` 的规则不再回读。

## 7. 快车道的最小输入

```text
按这个 prompt 做，不要改文案：
<粘贴 prompt 或给路径>

素材：./assets/（logo、截图、录屏）
音乐：./music.mp3
时长/画幅：60 秒 / 16:9
必须出现：产品名、URL、日期
不要出现：……
```

一句话版本：

> 输入已齐，走快车道：只做 1 个方向，先给 640 长边预览；不要生成 3 个方向，不要 1080p 对比图。

## 8. 快车道验收

- [ ] `BRIEF.md` 记录了用户输入和所有假设
- [ ] 只做了 1 个方向（或用户明确要求的对比）
- [ ] 对比图 ≤3 张，单张长边 ≤640
- [ ] `plan.json` 覆盖全时长，无 gap/overlap
- [ ] 预览是 640 长边 / 12fps，能看到节奏和音画同步
- [ ] P2 后才开始 1080p 终渲
- [ ] 终版 `check_delivery.py` 无 error；首帧/中段/结尾抽检过
